# C 区宿舍庭院板块（zone/dorm-c · c_court）合并说明

本分支新增 C 区宿舍庭院细节场景 `campus3d/dorm-c/dorm-c.html`（`dorm-c-scene.js` + 共用外壳 `campus3d/zone-kit/`），按学校官网绵阳校区导览图（`ref/official/c_court_kindergarten/`，自西南偏南斜俯视）与平面图（0.4 米/像素）重建。坐标与全景一致：`x = (px − 1024) × 0.4`，`z = (py − 999) × 0.4`（米），所以 `zone_species.pos_x / pos_z` 直接是全景世界坐标。

**本分支没有改 `zones.json` 和 `campus_layout.json`**（多个板块分支同时在改这两个文件，留到合并时一次性处理）。`zones.json` 里 `catalog` 为 `null` 时场景用 `dorm-c-scene.js` 内置的物种目录，所以场景本身可以独立打开；但主页入口和后端写权限依赖下面第 1 节的改动。

## 1. `zones.json` → `c_court`（必须改，否则主页进不去、不能增删）

```json
{
  "id": "c_court",
  "detail_scene": "dorm-c/dorm-c.html",
  "editable": true,
  "catalog": ["camphor", "osmanthus", "cherry", "crapemyrtle", "ginkgo", "azalea", "hedge", "cat", "magpie", "sparrow", "butterfly"],
  "intro": "翠湖东岸的 C 区学生公寓组团：两排错位的 7 栋板式公寓与 8 层双内院组合楼（C8–C10），楼间庭院绿树成荫；南侧是灰瓦坡顶的教师公寓，东南角是彩色坡屋顶的幼儿园与小型田径场。",
  "highlights": ["庭院绿地", "香樟", "樱花", "双内庭院", "幼儿园"]
}
```

- `detail_scene`（原为 `null`）：主页 `ecohome.js` 有这个字段时才显示“进入板块细节 3D 场景 →”，并追加 `?zone=c_court&back=…`。
- `editable: true`（原为 `false`）：后端 `ZoneSpeciesService` 按这个字段放行写操作（否则 403 `zone_readonly`）；场景里“✏️ 管理动植物”按钮也只在可编辑时显示（`?test=1` 除外）。
- `catalog`：与 `dorm-c-scene.js` 的 `species.catalog` 一致。`hedge`（绿篱）只在目录里，场景里默认没有个体。
- `polygon` / `center`（建议改）：现有多边形东界在 x = 800，幼儿园（784–985）和停车场基本在板块外，主页上点幼儿园不会选中本板块。建议改为
  `[[491,1045],[640,1045],[830,1400],[830,1630],[990,1630],[990,1815],[340,1815],[340,1690],[510,1600],[517,1202]]`，`center` 改为 `[680, 1450]`。已核对：与 `teaching_green`（同纬度西界 x ≈ 950–1100）不重叠。

## 3. 数据库 / 演示存储

- `zone_species` 里还没有 `c_court` 的记录，没有旧数据需要迁移。
- 原有个体的 `seed_ref` 按物种编号（`cherry#0`…`cherry#5`、`osmanthus#0`…），顺序由 `dorm-c-scene.js` 的 `species.seeds` 决定。**上线后不要调整 seeds 的顺序**，否则已保存的移植 / 移除记录会作用到别的个体上。
- 无后端时，编辑器的演示模式存在 `localStorage["c_court-species-demo:c_court"]`。
- `area_code` 为 `MY-ECO-DORM-C`（`zones.json` 里已有）。

## 4. 本分支对共用外壳 `zone-kit/` 的改动

只改了 `zone-build.js`，内容**与 zone/cdorm-sports 分支的同一文件逐字节一致**（直接取自该分支），三处都是 bug 修复，没有改接口，合并时不会冲突：

1. `hedge()`：`roundedBox()` 焊接后没有 `uv`，原代码读 `uv.count` 抛错，场景加载失败（本场景首次加载时就是这个错误）。现在补建 `uv`。
2. `polyL()`：`ShapeGeometry` 先 `toNonIndexed()` 再 `fixWinding()`，否则翻转时面片错乱（本场景的幼儿园跑道 / 内场、公寓入口铺装受影响）。
3. 铁丝网材质改为半透明混合，远景不再变成黑墙（本场景的幼儿园围栏受影响）。

**发现但未修改**（属于共用外壳，留给外壳维护者）：`zone-species.js` 的 `canPlace()` 把已经是像素的 `rp * 0.55` 再传给 `K.classAt(x, z, padM)`，而 `classAt` 会再除以 0.4，所以“离建筑 / 铺装留半个冠幅”的实际余量是设计值的 2.5 倍。种植仍然可用，只是靠墙、靠路的位置比预期更难种。本场景的原有个体位置已按现有（偏严）规则校验通过。

## 5. 已知差异（与导览图相比）

- 树木数量受 `EcoLife` 上限 320 株限制，楼间庭院比导览图稀疏；树种由 `EcoLife` 按离水 / 离路距离分配（湖边多为垂柳），不完全对应导览图的单株。
- 板楼立面统一用 `dormc` 风格（砖红 + 灰色腰线），导览图上部分山墙为灰色涂料。
- 幼儿园各楼的位置与体量按导览图估计（平面图只有一个外框），田径场按导览图放在西侧。
- 无后端时静态服务器会对 `/api/zones/c_court/species`、`/api/zones/me` 返回 404（浏览器控制台记为资源加载失败），编辑器自动进入演示模式；接上 Java 后端后不会出现。
